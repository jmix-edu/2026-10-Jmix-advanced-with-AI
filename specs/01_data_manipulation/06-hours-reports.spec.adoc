== Цель

Показать, сколько подтверждённого времени ушло на проекты: сводку по проекту и
пользователю за выбранный период и сводку по каждому проекту для менеджера.
Только чтение, ничего не сохраняется.

== В области

* Сервис `HoursReportService` с двумя методами: сводка по проекту и
  пользователю за период (KeyValue) и список `ProjectSummary`.
* DTO-сущность `ProjectSummary` (не хранится в БД).
* Экран «Отчёт по часам» и пункт меню.
* Подписи DTO, экрана и столбцов в `messages_en.properties`.
* Интеграционный тест сервиса.

== Вне области

* Второе хранилище и биллинг — следующая спека.
* Права: кто видит какие проекты (M3). Пока отчёт показывает все проекты.
* Оформление экрана (M2), экспорт, графики.
* Changelog: схема не меняется.

== Какое время считается

Во всех суммах — только списания в `APPROVED` и `CLOSED`. Архивные (soft
delete) не учитываются: Jmix отфильтровывает их сам, а при архивации проекта
архивируются и его списания (спека `04-traits`).

== Сводка по проекту и пользователю

`HoursReportService.loadHoursByProjectAndUser(LocalDate from, LocalDate to)`
→ `List<KeyValueEntity>`.

* Запрос JPQL через `DataManager.loadValues(...)`, своего класса нет:
+
[source,sql]
----
select e.task.project.id, e.user.id, sum(e.spentTime), count(e)
from ts_TimeEntry e
where e.date between :from and :to
  and e.status in :statuses
group by e.task.project.id, e.user.id
----
+
Группировка по `id`, а не по ссылке на сущность: так SQL одинаково валиден
в PostgreSQL и HSQLDB. Проекты и пользователи строк подгружаются вторым и
третьим запросом по списку `id`, без N+1.
* Свойства строки: `project` (`Project`), `user` (`User`), `totalTime`
  (`SpentTime`), `entryCount` (`Long`).
* `SUM` по колонке `SpentTime` проходит мимо конвертера и возвращает число
  (проверено: `BigDecimal` на HSQLDB). Сервис переводит его в `SpentTime`,
  поэтому грид показывает `ч:мм` через тип `spentTime` без своего рендерера.
* Период включает обе границы. `from` и `to` обязательны, `from` не позже
  `to` — иначе `IllegalArgumentException`.
* Сортировка — по имени проекта, затем по логину пользователя.

== ProjectSummary

DTO в пакете `com.company.timesheets.entity`:
`@JmixEntity(annotatedPropertiesOnly = true)`, без таблицы и changelog.

[cols="2,2,4",options="header"]
|===
| Атрибут | Тип | Смысл

| `id`               | `UUID`          | `@JmixId`, равен `id` проекта
| `project`          | `Project`       | `@InstanceName` через имя проекта
| `client`           | `Client`        | клиент проекта
| `status`           | `ProjectStatus` | статус проекта
| `totalTime`        | `SpentTime`     | подтверждённое время (`APPROVED`, `CLOSED`) по проекту за всё время
| `currentMonthTime` | `SpentTime`     | время с 1-го числа текущего месяца по сегодня (дата сервера)
| `participantCount` | `Integer`       | число уникальных пользователей среди участников (одного пользователя с двумя ролями считаем один раз)
|===

* `HoursReportService.loadProjectSummaries()` → `List<ProjectSummary>`.
* Проекты — все неархивные, и открытые, и закрытые: менеджеру нужен итог и по завершённым. Сортировка по имени.
* Без N+1: проекты с клиентами — одним запросом, суммы времени и число
  участников — по одному агрегатному запросу с `group by` по проекту.
  Проект без списаний и участников даёт `0:00` и `0`.
* Экземпляры создаются через `Metadata.create()`, не конструктором.
* `SpentTime` у атрибутов DTO — тип `spentTime` по умолчанию, поэтому грид
  покажет `ч:мм` без своего рендерера.

== Экран «Отчёт по часам»

Свой экран, не CRUD от Studio — пишу я по скиллу `jmix-views`.

* `HoursReportView`, id `ts_HoursReportView`, маршрут `hours-report`, пункт
  меню после «Time entries».
* Период: два `datePicker` «С» и «По», по умолчанию текущий месяц целиком (с 1-го по последнее число), и кнопка
  «Показать». Пустая дата или «С» позже «По» — уведомление, загрузки нет.
* Грид 1 — сводка по проекту и пользователю: `keyValueCollection` с
  загрузчиком через сервис; столбцы «Проект», «Пользователь», «Время»
  (`ч:мм`), «Списаний».
* Грид 2 — `ProjectSummary`: `collection` с загрузчиком через сервис;
  столбцы «Проект», «Клиент», «Статус», «Всего», «За месяц», «Участников».
  От периода не зависит, загружается при открытии.
* Логика расчёта — только в сервисе, контроллер лишь передаёт период.

== Тест

`HoursReportServiceTest` — `@SpringBootTest`, `@ExtendWith(AuthenticatedAsAdmin.class)`,
данные через `DataManager` с переходами статусов по правилам `05`, уборка
через `JdbcTemplate`, как в `TimeEntryRulesTest`. Проверки — только по
проектам, созданным тестом.

* Сводка по проекту и пользователю:
** считает `APPROVED` и `CLOSED`, не считает `NEW` и `REJECTED`;
** границы периода включены, списания за день до и после — нет;
** группировка: два пользователя на одном проекте и один пользователь на
   двух проектах дают отдельные строки с верными суммой и числом;
** архивное списание не считается;
** `from` позже `to` — `IllegalArgumentException`.
* `ProjectSummary`:
** `totalTime` и `currentMonthTime` различаются, если есть списание в
   прошлом месяце;
** `participantCount` считает пользователя с двумя ролями один раз;
** проект без списаний — `0:00` и `0`;
** клиент и статус проекта на месте.

== Критерии приёмки

Проверяет Claude:

. Первая сводка — один JPQL-запрос `loadValues` в сервисе, без своего
  класса; `ProjectSummary` — DTO без `@Entity`, таблицы и changelog.
. Сервис не делает запросов в цикле по проектам.
. `HoursReportServiceTest` покрывает каждый пункт раздела «Тест», зелёный,
  проходит дважды подряд и не оставляет строк.
. Ключи сообщений для DTO, экрана, столбцов и пункта меню есть.
. Gate 1 по каждому затронутому файлу и Gate 2 (`gradle clean test`) зелёные.

Проверяете вы (чек-лист Gate 3, после перезапуска, на данных сидера):

. Пункт меню открывает экран без ошибок; период по умолчанию — текущий месяц.
. Первый грид показывает строки проект × пользователь, время в `ч:мм`;
  смена периода и «Показать» меняют строки.
. Второй грид показывает все проекты сидера, включая закрытый
  `Legacy Support`, с временем в `ч:мм` и числом участников.
. Пустая дата или «С» позже «По» — уведомление, а не ошибка.
