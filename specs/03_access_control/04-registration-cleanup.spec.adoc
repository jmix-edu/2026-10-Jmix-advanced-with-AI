= 03_access_control / 04 — Очистка неактивированных регистраций
:toc:
:status: реализована, ждёт Gate 3

== Цель

Учётные записи, созданные регистрацией (спека 03/03) и не активированные
до конца срока ссылки, удаляются сами по расписанию Quartz. Таблица
пользователей не копит мусор, адрес можно зарегистрировать заново.

== В области

* Сервисный метод очистки и задание Quartz, которое его вызывает.
* Расписание в свойствах, регистрация задания бинами Spring.
* Тест очистки, включая вызов без аутентификации, как из планировщика.

== Вне области

* Письмо-напоминание перед удалением.
* Очистка пользователей, отключённых администратором (`active = false`,
  `needsActivation = false`): это обычные учётные записи.
* Архив или журнал удалённых сверх строки в логе.

== Что уже есть

* Аддон Quartz подключён (`jmix-quartz-starter`, `jmix-quartz-flowui-starter`),
  своих заданий в проекте пока нет. Задания видны в «Administration →
  Quartz → Jobs».
* Кандидаты на удаление — `needsActivation = true` и
  `activationTokenExpiresAt < now`. Флаг добавлен в 03/03 именно для этого.
* У `User` нет мягкого удаления (нет `@DeletedDate`), `remove` удаляет
  строку. Уникальный `username` после этого свободен.
* На `User` ссылаются `ProjectParticipant.user` и `TimeEntry.user` без
  `@OnDeleteInverse`: удаление пользователя со ссылками упадёт на внешнем
  ключе. Неактивированного пользователя администратор мог успеть добавить
  в проект (вопрос 1).
* Задание выполняется в потоке планировщика без пользователя. Любой вызов
  `DataManager` без аутентификации бросает «Authentication is not set», и
  ни один гейт этого не ловит. Поэтому метод сервиса помечен
  `@Authenticated` (правило `jmix-run-background-code`), а тест вызывает его
  без аутентификации.

== Очистка

`RegistrationService.removeExpiredRegistrations()`, `@Authenticated`:

* выбирает пользователей с `needsActivation = true` и
  `activationTokenExpiresAt < now` через `UnconstrainedDataManager`;
* пропускает тех, на кого есть ссылки (участие в проекте, списания), и пишет
  о них в лог `warn` (вопрос 1);
* остальных удаляет вместе с их строками `sec_role_assignment`, если такие
  есть (их не должно быть, но назначение мог добавить администратор);
* каждый пользователь удаляется отдельно: ошибка на одном не мешает
  остальным;
* возвращает число удалённых, пишет итог в лог `info`.

Удаление сразу после истечения срока, без дополнительного запаса (вопрос 2).

== Задание Quartz

* `ExpiredRegistrationsCleanupJob implements org.quartz.Job` (пакет
  `job`): `execute` только вызывает
  `registrationService.removeExpiredRegistrations()`. Бин сервиса внедряется
  через `@Autowired`: Quartz в Spring Boot создаёт задания через
  `SpringBeanJobFactory`.
* `@Configuration RegistrationCleanupJobConfiguration`: бины `JobDetail`
  (`storeDurably`, имя `expiredRegistrationsCleanup`, группа `timesheets`) и
  `Trigger` с `CronScheduleBuilder` из свойства.
* Свойство `timesheets.registration.cleanup-cron`, по умолчанию `0 0 * * * ?`
  — каждый час (вопрос 3).
* Повторный старт не создаёт дубль: Jmix Quartz в своём `module.properties`
  включает `spring.quartz.job-store-type=jdbc` и
  `spring.quartz.overwriteExistingJobs=true`, и Spring Boot перезаписывает
  задание и триггер с теми же ключами. Смена cron в свойстве применяется при
  следующем старте.
* В профиле `test` планировщик не запускается
  (`spring.quartz.auto-startup=false`), тест вызывает метод сам.

== Тесты

`RegistrationCleanupTest` (`@SpringBootTest`), данные создаются от system,
*вызов очистки — без аутентификации*:

* удаляется: `needsActivation = true`, срок истёк;
* остаётся: `needsActivation = true`, срок не истёк; активный; отключённый
  администратором (`active = false`, `needsActivation = false`) с прошедшим
  сроком;
* остаётся с предупреждением: просроченный неактивированный, у которого есть
  участие в проекте;
* после удаления адрес снова регистрируется (`register` создаёт нового
  пользователя);
* бин `JobDetail` с ключом `timesheets.expiredRegistrationsCleanup` есть в
  контексте, у триггера cron из свойства.

== Решения по ревью

. Неактивированного со ссылками пропускаем и пишем в лог. Ссылки считаются
  вместе с мягко удалёнными строками: они тоже держат внешний ключ.
. Удаляем сразу после истечения срока.
. Расписание — каждый час.

== Критерии приёмки

. В «Administration → Quartz → Jobs» есть задание
  `expiredRegistrationsCleanup` с расписанием из свойства.
. Неактивированный пользователь с истёкшим сроком через час (или при
  ручном запуске задания из «Jobs») исчезает из «Users», его адрес можно
  зарегистрировать заново.
. Активные, отключённые администратором и ещё не просроченные
  пользователи не трогаются.
. Задание работает без пользователя (из планировщика): в логе нет
  «Authentication is not set».
. `gradle clean test` зелёный, включая `RegistrationCleanupTest`.
