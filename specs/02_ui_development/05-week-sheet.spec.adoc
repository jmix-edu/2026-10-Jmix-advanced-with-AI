== Цель

Учебный пример интеграции сторонней JS-библиотеки в Jmix 3 / Vaadin 25.
Сотрудник заполняет неделю как в Excel: строки — задачи, столбцы — дни,
в ячейке часы. Можно вставить диапазон из буфера, протянуть значение, быстро
пройтись по ячейкам клавиатурой. Сохранение одной кнопкой, все правила
списаний (спека 01/05) работают как раньше.

Это та таблица «задача × дни недели», которую спека 02/01 вынесла за рамки.

== В области

* Интеграция RevoGrid — открытого аналога Handsontable (решение 2). Аддоны
  Vaadin отпадают (см. «Кандидаты»).
* Java-компонент-обёртка над JS-таблицей: данные с сервера в браузер, правки
  из браузера на сервер.
* Экран «Week sheet» рядом с «My week»: неделя в URL, листание недель.
* Сервис, который превращает правки ячеек в создание, изменение и
  удаление `TimeEntry`.
* Тест сервиса.
* Ключи сообщений.

== Вне области

* Формулы, сортировка, фильтры, объединение ячеек.
* Таблица для руководителя по чужим списаниям, согласование из таблицы.
* Описание списания (`description`) в таблице: только часы. Описание —
  в форме списания, как сейчас.
* Стили под Aura сверх штатной темы библиотеки (решение 4).
* Мобильная вёрстка.

Проверено по проекту, npm, Maven Central и Vaadin Directory 28.10.2026.

* *Стек UI*: Vaadin 25.1 (`flow-server` 25.1.14), Jmix 3.0.2, тема Aura, сборка
  фронтенда Vite, production-сборка внутри Docker (спеки 04/01–02). Своих
  TS/JS-файлов в `src/main/frontend` пока нет.
* *Свои компоненты*: `SpentTimeField` с загрузчиком XML
  (`SpentTimeFieldLoader`, XSD, `TimesheetsComponentsConfiguration`,
  спека 02/04) и `ColorPicker` на `@Tag("input")` — пример простого
  элемента без JS. Образец регистрации компонента в XML уже есть.
* *Неделя*: `MyWeekView`, `WeekPeriod` (понедельник–воскресенье), неделя в
  URL (`RouteSupport.setQueryParameter`).
* *Время*: datatype `SpentTime` (минуты, ввод и вывод `ч:мм`).
* *Правила списаний* (спека 01/05, `TimeEntryRulesListener`):
** править можно только `NEW`; в `APPROVED`/`REJECTED` меняется только
   статус; `CLOSED` не меняется и не удаляется;
** `0:00` нельзя, за день не больше 24 часов;
** нельзя списывать на неактивную задачу и задачу закрытого проекта.
* *Права*: `own-time-entries` и `project-participation` (спека 03/01) — через
  защищённый `DataManager` сотрудник видит и меняет только свои списания и
  только в своих проектах.

== Предложение

*Своя обёртка над JS-библиотекой* — именно её учебный пример и показывает:
npm-зависимость, JS-модуль, обмен данными между сервером и браузером,
регистрация компонента в XML Jmix. Аддоны либо мёртвые, либо платные,
аналог без JS не показывает интеграцию.

«Наш аналог» — открытая JS-библиотека того же рода (решение 1). Берём
*RevoGrid* (решение 2):

* MIT, без лицензионных оговорок для курса и прода; платный Pro нам не нужен;
* живой: релизы каждую неделю, последний — 4.29.1 от 23.10.2026;
* сам является web component (`<revo-grid>`, Stencil). Учебная польза:
  видно, как Vaadin работает с готовым custom element, и где всё равно нужен
  свой тонкий JS-модуль — функции (правило «только чтение» для ячейки,
  обработчики) с сервера не передать;
* в бесплатном ядре: вставка из Excel и Google Sheets, выделение и
  протягивание диапазона (autofill), клавиатурная навигация.

== Компонент `WeekSheet`

=== Java

* `com.company.timesheets.component.WeekSheet extends Component`,
  `@Tag("ts-week-sheet")`,
  `@NpmPackage(value = "@revolist/revogrid", version = "4.29.1")`,
  `@JsModule("./src/components/week-sheet.ts")`. Версия закреплена точно, без
  `^`: библиотека выходит каждую неделю.
* Ничего не знает о `TimeEntry`: принимает модель
  `WeekSheetModel` (record: дни, строки, ячейки) и отдаёт события правок. Так
  компонент можно переиспользовать и проверять отдельно.
* Сервер → браузер: `getElement().setPropertyJson("model", …)` целиком при
  загрузке недели и после сохранения. В Vaadin 25 JSON-API Element перешёл
  с `elemental.json` на Jackson — точные сигнатуры сверю при реализации
  (`jmix-verify-api-symbol`).
* Браузер → сервер: DOM-событие `week-sheet-change` с массивом правок
  `{row, day, text}` в `event.detail`, на Java — `ComponentEvent` с
  `@DomEvent` и `@EventData`. Правки копятся в браузере, на сервер уходят
  пачкой: вставка диапазона — одно событие, а не сто.
* Свойство `readOnly` — вся таблица только для чтения.
* Загрузчик XML `WeekSheetLoader` и элемент `<weekSheet>` в существующем
  `timesheets-components.xsd`, как у `SpentTimeField`.

=== JS

`src/main/frontend/src/components/week-sheet.ts` — custom element
`ts-week-sheet` на Lit (Lit уже есть в зависимостях Vaadin), внутри —
`<revo-grid>`:

* регистрирует элементы RevoGrid (загрузчик пакета; точную точку входа для
  Vite — `loader` или `custom-element` — сверю при реализации);
* из свойства `model` собирает `columns` (задача + семь дней + итог) и
  `source` (строки) для `<revo-grid>`; при смене модели обновляет их, не
  пересоздаёт таблицу;
* ячейка только для чтения — функция `readonly` у колонки по признаку из
  модели; подсказка — свой `cellTemplate` с `title`;
* слушает `afteredit` RevoGrid: и одиночная правка, и вставка или
  протягивание диапазона приходят одним событием — из него собирается
  пачка `{row, day, text}` для `week-sheet-change`;
* тема: штатная тема RevoGrid (свойство `theme`), светлая или тёмная по
  схеме, которую выставляет переключатель темы приложения (спека 02/03);
  модуль следит за её сменой. Точные имена тем RevoGrid 4.29 сверю при
  реализации;
* при отключении элемента ничего не держит: обработчики снимаются,
  RevoGrid уничтожается вместе с DOM;
* строка итогов по дням и столбец итога по задаче считает сама таблица для
  мгновенного отклика; итог после сохранения приходит с сервера;
* значение ячейки — строка как ввёл пользователь, разбор — на сервере.

* `WeekSheet` в XML экрана через `<weekSheet>`.

== Модель недели и правила ячеек

`WeekSheetService` (`service`), защищённый `DataManager`.

*Строки*: задачи, на которые текущий пользователь может списывать (активная
задача, открытый проект, пользователь — участник), плюс задачи, на которые у
него уже есть списания этой недели (даже если задача с тех пор закрыта).
Сортировка: проект, задача.

*Ячейка (задача, день)*:

[cols="2,1,3",options="header"]
|===
| Списания в ячейке | Правка | Что видно
| нет | да, если задачу можно списывать | пусто
| одно `NEW` | да | время списания
| одно `REJECTED` | нет | время, подсказка с причиной отклонения
| одно `APPROVED` или `CLOSED` | нет | время, подсказка со статусом
| несколько | нет | сумма, подсказка «N списаний — правьте в My week»
|===

*Применение правок* — `apply(week, changes)`, одна транзакция:

* текст разбирается datatype `SpentTime` (`1:30`, `2` — как в
  `SpentTimeField`; `1.5` он не понимает); не разобрался → ошибка ячейки,
  ничего не сохраняется;
* пусто → нет списания: было одно `NEW` — удалить (решение 3, soft delete
  как везде), не было —
  ничего;
* значение → создать `NEW` или изменить время единственного `NEW`;
* ячейка, которую нельзя править, — отказ (защита от подделки события из
  браузера);
* все изменения одним `SaveContext`: `TimeEntryRulesListener` проверяет 24
  часа на день с учётом всей пачки. Нарушение → откат всего, сообщение
  правила, правки в таблице остаются, ячейки дня с ошибкой подсвечены.
* После успеха — модель недели заново из базы.

== Тесты

`WeekSheetServiceTest` (правила — то, что руками проверять долго):

* создание, изменение и удаление списания из правок;
* `APPROVED`, `CLOSED`, ячейка с двумя списаниями — отказ, в базе ничего не
  изменилось;
* 24 часа: пачка, которая в сумме за день превышает лимит, не сохраняется
  целиком;
* неразборчивый текст — ошибка именно этой ячейки;
* сотрудник не видит и не меняет чужие списания (под его аутентификацией).

браузер не запускают.

== Решения ревью

. «Наш аналог» — открытая JS-библиотека того же рода, что Handsontable.
. Библиотека — RevoGrid 4.29.1 (MIT).
. Очистка ячейки с одним `NEW` удаляет списание (soft delete). Ячейки с
  другими статусами только для чтения, их не очистить.
. Оформление — штатная светлая и тёмная тема RevoGrid по переключателю темы
  приложения, без подгонки под токены Aura.
. Компонент регистрируется в XML: `<weekSheet>`, загрузчик и XSD, как у
  `SpentTimeField`.

== Отличия реализации от черновика

* *Свой элемент без Lit*: обычный `HTMLElement`. Всю разметку рисует
  RevoGrid, шаблонов у нас нет, лишняя зависимость не нужна.
* *Второй npm-пакет* `@stencil/core` 4.43.5: standalone-сборка RevoGrid
  импортирует рантайм Stencil, но не объявляет его в зависимостях. Без него
  production-сборка падает на «Rollup failed to resolve import». Версия — та,
  с которой собран RevoGrid 4.29.1.
* *Итоги*: закреплённая нижняя строка «Total: ч:мм» (по дням и за неделю в
  подписи), без столбца итога по задаче: для столбца пришлось бы
  перерисовывать ячейки вне правки, строка пересчитывается надёжно.
* *Нарушение правила 24 часов* — сообщением, без подсветки ячеек: слушатель
  правил сообщает текст, но не ячейку. Подсвечиваются ошибки разбора и
  закрытые ячейки.
* *`0` и `0:00` — нет времени*, как пустая ячейка: в таблице ноль значит
  «ничего», а правила не принимают списание `0:00`.
* *Одно `REJECTED` в ячейке* — пусто (отклонённое время не засчитано, как в
  итогах «My week»), подсказка с временем и причиной.
* *Сервис и модель названы* `WeekTimesheetService` и `WeekTimesheet` (домен),
  чтобы не путать с компонентом `WeekSheet` и его `WeekSheetModel`.
* *Тесты*: кроме `WeekTimesheetServiceTest` (7) — `WeekSheetViewUiTest` (3):
  экран из `<ts:weekSheet>`, правки из браузера через имитацию DOM-события,
  сохранение.
* *Документ* с полным разбором интеграции: `docs/revogrid-integration.adoc`.
* *Формат проверяется сразу, в браузере* (по итогам Gate 3; в черновике
  разбор был только на сервере при сохранении):
** введённый или вставленный текст приводится к виду сервера: `1` → `1:00`,
   `0:5` → `0:05`, `0` и `0:00` → пусто. Делается в `beforeedit` и
   `beforerangeedit`, до того как RevoGrid запишет значение, поэтому в
   ячейке и на сервере один и тот же текст;
** текст, который не время (`zzz`, `1:75`), остаётся как введён, ячейка
   сразу подсвечивается, подсказка — `invalidText` из модели (сообщения живут
   на сервере, поэтому текст приходит с моделью);
** правка ячейки снимает с неё ошибку сервера; следующее сохранение
   проверяет заново;
** сервер по-прежнему разбирает и проверяет всё сам: браузеру не доверяем.
* *CSS ячеек сильнее темы RevoGrid*: правило компактной темы
  `revo-grid:is([theme=compact],[theme=darkCompact]) revogr-data .rgCell`
  задаёт `box-shadow` (вертикальные границы) и перебивало
  `ts-week-sheet .ts-week-sheet__error` — рамка ошибки не появлялась. Правила
  ячеек теперь с префиксом `ts-week-sheet revo-grid revogr-data .rgCell`.
* *Vaadin создаёт в корне проекта* `package.json`, `package-lock.json`,
  `tsconfig.json`, `types.d.ts`, `vite.config.ts` при первой сборке с
  npm-пакетом. Их принято коммитить; `node_modules` и
  `vite.generated.ts` уже в `.gitignore`.

== Критерии приёмки

. «Week sheet» открывается из меню у сотрудника, подрядчика и руководителя,
  неделя в URL, листание работает.
. Строки — задачи пользователя, ячейки по правилам из таблицы выше,
  нередактируемые ячейки с подсказкой.
. Текст не время подсвечивается сразу, с подсказкой; `1` становится `1:00`
  при вводе и при вставке.
. Вставка блока 3×5 из Excel/LibreOffice и протягивание значения работают.
. «Save» создаёт, меняет и удаляет списания, «My week» показывает то же.
  Превышение 24 часов — сообщение, ничего не сохранено, правки на месте.
. Уход с несохранёнными правками спрашивает подтверждение.
. Production-сборка (`-Pvaadin.productionMode=true bootJar` и Docker-образ)
  включает библиотеку, в консоли браузера нет ошибок.
. `gradle clean test` зелёный, включая `WeekSheetServiceTest`.
