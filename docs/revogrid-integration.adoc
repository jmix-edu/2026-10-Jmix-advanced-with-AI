= Интеграция JS-библиотеки в Jmix 3 / Vaadin 25 на примере RevoGrid
:toc: left
:toclevels: 3
:icons: font
:source-highlighter: rouge

Учебный разбор: как сторонняя JS-библиотека становится обычным компонентом Jmix, который объявляют в XML
экрана, настраивают в Studio и проверяют тестами. Пример — экран «Week sheet»: табель недели в стиле
Excel на библиотеке https://rv-grid.com[RevoGrid]. Требования и решения — в
`specs/02_ui_development/05-week-sheet.spec.adoc`.

== Что получилось

Сотрудник открывает «Timesheets → Week sheet» и видит неделю таблицей: строки — задачи, столбцы — дни,
в ячейках часы (`1:30`, `2`). Можно:

* печатать в ячейки и ходить по ним клавиатурой;
* выделить диапазон и вставить блок из Excel или Google Sheets;
* протянуть значение за угол выделения (autofill);
* очистить ячейку — время этого дня удаляется;
* сохранить всё одной кнопкой или отменить.

Итоги по дням и за неделю пересчитываются сразу, в закреплённой нижней строке. Ячейки, которые менять
нельзя (утверждённое, закрытое, отклонённое списание, несколько списаний за день, закрытая задача),
серые и объясняют причину во всплывающей подсказке. Сохранение проходит через те же правила списаний,
что и форма списания: например, не больше 24 часов в день.

== Почему RevoGrid

Выбор сделан на ревью спеки, кратко:

[cols="1,3",options="header"]
|===
| Кандидат | Почему нет или да
| Handsontable 18 | Бесплатно только для оценки и некоммерческого использования вне продакшена
| Аддон Handsontable for Flow | Поддерживает Vaadin 10–13, для Vaadin 25 не обновлялся
| Vaadin Spreadsheet, Grid Pro | Работают, но под коммерческой лицензией Vaadin
| Jspreadsheet CE | MIT, но релизов нет больше года
| *RevoGrid 4.29.1* | *MIT, релизы каждую неделю, сам является web component, вставка из Excel и autofill в бесплатном ядре*
|===

Обёртка устроена так, что библиотека спрятана в одном TypeScript-файле. Замена на другую — правка этого
файла и строки `@NpmPackage`, Java-код и экран не меняются (см. <<replace>>).

Слои и направление зависимостей:

[source]
----
week-sheet-view.xml ──► WeekSheetView ──► WeekTimesheetService ──► DataManager, правила списаний
                             │                     │
                             │              WeekTimesheet (сущности)
                             ▼
                        WeekSheet (Java) ◄──► <ts-week-sheet> (TS) ──► <revo-grid> (RevoGrid)
                             ▲
                        WeekSheetModel (только тексты и флаги)
----

Компонент ничего не знает о списаниях, сервис ничего не знает о UI. Связывает их экран: переводит
`WeekTimesheet` в `WeekSheetModel` и правки ячеек — в `CellEdit`.

== Шаг 1. npm-пакет в сборке Vaadin

[source,java]
----
@NpmPackage(value = "@revolist/revogrid", version = "4.29.1")
----

* Vaadin собирает все `@NpmPackage` из classpath и пишет их в `package.json` в корне проекта. При
  следующей сборке фронтенда пакет ставится в `node_modules`, а Vite включает его в бандл.
* Версия точная, без `^`: RevoGrid выходит каждую неделю, и без фиксации сборка в Docker могла бы
  получить другую версию, чем на машине разработчика.
* *Неявная зависимость.* Standalone-сборка RevoGrid (`@revolist/revogrid/standalone/...`) импортирует
  рантайм Stencil — `@stencil/core/internal/client`, — но не объявляет его в зависимостях пакета. Без
  него production-сборка падает:
+
[source]
----
[vite]: Rollup failed to resolve import "@stencil/core/internal/client"
from ".../node_modules/@revolist/revogrid/standalone/revo-grid.js"
----
+
Поэтому на `WeekSheet` второй `@NpmPackage(value = "@stencil/core", version = "4.43.5")` — та версия,
с которой собран RevoGrid 4.29.1 (её видно в `devDependencies` его `package.json`). При обновлении
RevoGrid сверяйте и её.
* *Типы проверяются при сборке.* Production-сборка Vaadin прогоняет проверку TypeScript: ошибка
  типов в `week-sheet.ts` останавливает `bootJar`, а не всплывает в браузере.
* *Dev-режим* (`bootRun`): Vaadin замечает новый пакет и при первом запуске пересобирает dev-бандл.
  Этот запуск заметно дольше обычного, следующие — как раньше.
* *Production* (`./gradlew -Pvaadin.productionMode=true bootJar`, Docker-образ из спеки 04/02):
  пакет попадает в production-бандл внутри jar. В рантайме ни npm, ни интернет не нужны.

== Шаг 2. Свой custom element

[source,java]
----
@Tag("ts-week-sheet")
@JsModule("./src/components/week-sheet.ts")
public class WeekSheet extends Component implements HasSize, HasStyle {
----

* `@Tag` — какой HTML-элемент Vaadin создаст в браузере для этого компонента.
* `@JsModule` — путь от `src/main/frontend`. Vaadin подключает модуль в бандл; модуль определяет
  элемент (`customElements.define('ts-week-sheet', ...)`). Имена в `@Tag` и в `define` должны
  совпадать.
* TypeScript разрешён: Vite компилирует его при сборке. Типы RevoGrid (`import type`) помогают
  редактору и исчезают из бандла.

*Почему свой элемент, а не `@Tag("revo-grid")` напрямую.* RevoGrid сам является web component, и
многие его свойства можно задать из Java. Но часть настройки — функции: правило «эта ячейка только для
чтения» (`readonly: (cell) => ...`), атрибуты ячейки (`cellProperties`). Функцию с сервера в браузер
не передать — только данные. Поэтому тонкий слой на TypeScript нужен всё равно: он получает данные и
сам строит из них функции.

Элемент — обычный класс `HTMLElement`, без Lit: всю разметку рисует RevoGrid, шаблонов у нас нет.
Жизненный цикл:

* `connectedCallback` — элемент попал на страницу. Создаём `<revo-grid>` один раз, подписываемся на
  его события и на смену темы приложения;
* `disconnectedCallback` — экран закрыт. Снимаем наблюдателя темы, чтобы ничего не держало ссылку на
  элемент. Сам грид уходит вместе с DOM.

== Шаг 3. Данные с сервера в браузер

[source,java]
----
public void setModel(WeekSheetModel model) {
    getElement().setPropertyBean("model", model);
}
----

* В Vaadin 25 JSON-API элемента построен на Jackson 3 (`tools.jackson`), а не на `elemental.json`, как
  было в 24. `setPropertyBean` сериализует любой объект, record'ы в том числе.
* В браузере это просто присваивание свойства: `element.model = {...}`. Сеттер `set model(...)` в
  TypeScript перестраивает колонки и строки RevoGrid.
* Модель отправляется целиком при загрузке недели, после сохранения и при отмене. Для таблицы недели
  это десятки строк — дешевле, чем синхронизировать изменения по одной.

Как выглядит модель в браузере:

[source,json]
----
{
  "rowHeader": "Task",
  "totalHeader": "Total",
  "days": [ { "key": "2026-10-26", "caption": "Mon 26.10" }, ... ],
  "rows": [
    {
      "key": "6c1f…",
      "caption": "[Atlas] Backend",
      "cells": [
        { "text": "1:30", "editable": true,  "hint": null },
        { "text": "2:00", "editable": false, "hint": "Approved, cannot be changed" },
        ...
      ]
    }
  ]
}
----

Ещё два свойства: `errors` (`setPropertyList`, список ошибок ячеек после неудачного сохранения) и
`readOnly` (`setProperty`, вся таблица только для чтения).

В модели есть и `invalidText` — подсказка для ячейки, текст которой не время. Формат браузер проверяет
сам, а сообщения приложения живут на сервере, поэтому текст подсказки приходит вместе с данными.

Ключи (`key`) — стабильные идентификаторы: id задачи и дата. Браузер присылает правки по ключам, а не
по номерам строк, поэтому ответ не зависит от порядка строк.

== Шаг 4. Правки из браузера на сервер

В браузере, после того как RevoGrid применил правку:

[source,ts]
----
this.dispatchEvent(new CustomEvent('week-sheet-change', { detail: { changes } }));
// changes: [{ row: "6c1f…", day: "2026-10-26", text: "1:30" }, ...]
----

На сервере:

[source,java]
----
getElement().addEventListener("week-sheet-change", this::onClientChange)
        .addEventData("event.detail.changes");
----

* `addEventData` — выражение, которое браузер вычислит в момент события и пришлёт вместе с ним.
  Без него сервер получит событие без данных: Vaadin отправляет только то, что попросили.
* `event.getEventData().get("event.detail.changes")` — Jackson `JsonNode` с массивом правок.
* *Пачка, а не по ячейке.* RevoGrid сообщает вставку диапазона и протягивание одним событием
  `afteredit`. Модуль собирает все изменённые ячейки и отправляет их одним `week-sheet-change`:
  вставка блока 3×5 — один запрос к серверу, а не пятнадцать.

*Браузеру не доверяем.* Событие может прислать что угодно, поэтому:

* компонент отбрасывает ячейки, которых нет в модели;
* перед вставкой диапазона модуль убирает из него закрытые ячейки (`beforerangeedit`) — это удобство
  для пользователя, а не защита;
* защита — в сервисе: при сохранении он заново решает по свежим данным, можно ли менять каждую ячейку.

*Формат — сразу в браузере.* Ждать «Save», чтобы узнать, что `zzz` не время, неудобно, поэтому модуль
проверяет формат сам, тем же правилом, что `SpentTimeDatatype` на сервере (`ч` или `ч:мм`, минут не
больше 59):

* `beforeedit` (одна ячейка) и `beforerangeedit` (вставка, протягивание) срабатывают *до* того, как
  RevoGrid запишет значение, и их `detail` можно менять. Здесь текст приводится к виду сервера:
  `1` → `1:00`, `0:5` → `0:05`, `0` → пусто. Поэтому в ячейке, в итогах и на сервере один и тот же
  текст, а набранное заново прежнее значение — не изменение;
* текст, который не время, остаётся как введён. `cellProperties` получает текущее значение ячейки
  (`model[prop]` в аргументе) и помечает её классом ошибки с подсказкой `invalidText` — без
  отдельного учёта, пометка следует за каждой правкой;
* правка ячейки снимает с неё ошибку сервера (`errors`): та была про старый текст.

Сервер всё равно разбирает каждый текст сам — проверка в браузере только для удобства.

== Шаг 5. Состояние компонента на сервере

`WeekSheet` хранит несохранённые правки в `Map` по ячейке:

* та же ячейка, изменённая дважды, — одна правка с последним текстом;
* ячейка, которой вернули исходный текст, — уже не правка. Поэтому кнопка Save гаснет, если пользователь
  всё вернул как было;
* `ChangeEvent` приходит после каждой пачки из браузера и после `setModel`: по нему экран включает и
  выключает Save и Discard.

Сервер — источник правды и о несохранённых изменениях: экран спрашивает `hasChanges()`, не обращаясь к
браузеру. Это и даёт подтверждение при уходе с экрана (шаг 9).

== Шаг 6. Компонент в XML Jmix

Чтобы писать `<ts:weekSheet>` в дескрипторе экрана, нужны три вещи.

. *Загрузчик* `WeekSheetLoader extends AbstractComponentLoader<WeekSheet>`: создаёт компонент через
  `UiComponents` и читает атрибуты (`width`, `height`, `classNames`, `css`, `readOnly`). `id` и
  `visible` читает базовый класс.
. *Регистрация* — бин `ComponentRegistration` в `TimesheetsComponentsConfiguration`: имя элемента →
  класс и загрузчик. Jmix ищет загрузчик по локальному имени элемента.
. *XSD* — элемент `weekSheet` в `timesheets-components.xsd`, расширяет `layout:baseComponent` из
  схемы Jmix. Это для подсказок в редакторе и для Studio, на работу в рантайме не влияет.

Для палитры и инспектора Studio компонент описан в `TimesheetsStudioComponents` (`@StudioComponent`).
Этот интерфейс читает только Studio, приложение его не вызывает.

В экране:

[source,xml]
----
<view xmlns="http://jmix.io/schema/flowui/view"
      xmlns:ts="http://company.com/timesheets/schema/components" ...>
    <layout expand="weekSheet">
        ...
        <ts:weekSheet id="weekSheet" width="100%"/>
    </layout>
</view>
----

В контроллере — как любой компонент: `@ViewComponent private WeekSheet weekSheet;`.

Модель — не атрибут XML: её даёт контроллер после загрузки данных.

== Шаг 7. Данные и правила: сервис

`WeekTimesheetService.load(monday)`:

* строки — задачи, на которые пользователь может списывать (активная задача открытого проекта, где он
  участник), плюс задачи, на которые у него уже есть списания этой недели;
* ячейка — все его списания задачи за день;
* загрузка через защищённый `DataManager`, так что row-level роли (спека 03/01) работают как везде.

Правила ячейки (`WeekTimesheet.DayCell`):

[cols="2,1,3",options="header"]
|===
| Списания в ячейке | Правка | Показывает
| нет, задача открыта | да | пусто
| одно `NEW`, задача открыта | да | его время
| одно `REJECTED` | нет | пусто (отклонённое время не засчитано), подсказка с причиной
| одно `APPROVED` или `CLOSED` | нет | время, подсказка со статусом
| несколько | нет | сумма, подсказка «правьте в My week»
| любые, задача закрыта | нет | сумма, подсказка «задача не принимает время»
|===

`WeekTimesheetService.apply(monday, edits)`:

* неделя загружается заново: решения принимаются по данным на момент сохранения, а не на момент
  открытия экрана;
* текст разбирается тем же datatype, что и в форме (`SpentTimeDatatype`): `1:30`, `2`. Пусто или `0` —
  нет времени;
* нет времени → `NEW`-списание удаляется (soft delete); время → создаётся новое `NEW` или меняется
  единственное `NEW`;
* закрытая ячейка или неразборчивый текст — ошибка этой ячейки, и *ничего не сохраняется*;
* все изменения — один `SaveContext`, один `dataManager.save`. Слушатель правил
  (`TimeEntryRulesListener`) проверяет их в одной транзакции: 24 часа в день считаются с учётом всей
  пачки. Нарушение откатывает всё, сервис возвращает текст правила.

Итог — `SaveResult`: сохранено (и сколько списаний изменено) или нет (ошибки ячеек или нарушение
правила). Исключение правила наружу не выходит.

== Шаг 8. Экран

`WeekSheetView` — `StandardView` без контейнеров данных.

* *Неделя в URL* — как в «My week»: параметр `week`, `WeekPeriod`, кнопки предыдущей и следующей
  недели. Ссылкой на неделю можно поделиться.
* *Модель* — `toModel(WeekTimesheet)`: подписи дней по локали пользователя, время в формате `ч:мм`,
  подсказки из `messages_en.properties`. Все тексты собираются здесь, компонент получает готовые
  строки.
* *Save* — `apply`, затем:
** сохранено → неделя загружается заново, уведомление;
** ошибки ячеек → `weekSheet.showErrors(...)`: ячейки подсвечены, текст пользователя остаётся;
** нарушение правила → уведомление с текстом правила, правки остаются.
* *Discard* — `setModel` с той же моделью: таблица возвращается к сохранённому состоянию.

== Шаг 9. Несохранённые правки при уходе

У `StandardView`, в отличие от `StandardDetailView`, своей проверки нет. Сделано так же, как в
`StandardDetailView` Jmix:

[source,java]
----
@Subscribe
public void onBeforeClose(final BeforeCloseEvent event) {
    if (!weekSheet.hasChanges() || !(event.getCloseAction() instanceof NavigateCloseAction navigate)) {
        return;
    }
    ContinueNavigationAction navigation = navigate.getBeforeLeaveEvent().postpone();
    UnknownOperationResult result = new UnknownOperationResult();
    viewValidation.showUnsavedChangesDialog(this)
            .onDiscard(() -> { navigation.proceed(); result.success(); })
            .onCancel(() -> { navigation.cancel(); result.fail(); });
    event.preventClose(result);
}
----

* `postpone()` останавливает навигацию Vaadin до ответа пользователя.
* `cancel()` обязателен: с React-роутером Vaadin незавершённая навигация зависает (так написано и в
  исходниках Jmix).
* Кнопки недели — переход внутри того же экрана, поэтому они спрашивают сами
  (`whenNoUnsavedChanges`) и при согласии сбрасывают правки до навигации.

Закрытие вкладки браузера и перезагрузка страницы не перехватываются: это отдельный механизм
(`beforeunload`), в пример не входит.

== Шаг 10. Стили и тема

* RevoGrid рисует в light DOM, без shadow DOM. Поэтому обычный CSS темы приложения достаёт до его
  ячеек: `themes/timesheets-aura/view/week-sheet.css`, подключён в `styles.css`.
* Классы ячеек задаёт модуль через `cellProperties`: `ts-week-sheet__locked`, `ts-week-sheet__error`,
  `ts-week-sheet__total`. RevoGrid не заменяет, а добавляет их к своему классу `rgCell`.
* *Специфичность.* Темы RevoGrid стилизуют ячейки длинными селекторами, например
  `revo-grid:is([theme=compact],[theme=darkCompact]) revogr-data .rgCell { box-shadow: ... }` —
  так нарисованы вертикальные границы. Правило `ts-week-sheet .ts-week-sheet__error` слабее, и красная
  рамка ошибки просто не появлялась: ни ошибки в консоли, ни предупреждения. Поэтому правила ячеек
  написаны как `ts-week-sheet revo-grid revogr-data .rgCell.ts-week-sheet__error` — заведомо сильнее
  темы. Проверить можно в DevTools: на вкладке Styles перечёркнутое свойство показывает, кто победил.
* Цвета — только токены, которые есть в Aura 25.1: `--vaadin-text-color-secondary`,
  `--vaadin-background-container`, `--aura-red-text`. Чужой или выдуманный токен не даёт ошибки,
  просто не работает.
* Пользовательский элемент по умолчанию строчный — `display: block` и минимальная высота, иначе
  RevoGrid не может разметить область прокрутки. Высоту даёт `expand="weekSheet"` у `layout` экрана.
* *Тёмная тема.* Переключатель приложения (спека 02/03) ставит `theme="dark"` на `<html>`. Модуль
  следит за этим атрибутом (`MutationObserver`) и переключает встроенную тему RevoGrid: `compact` или
  `darkCompact`.
* Надпись «RevoGrid» (attribution) не скрываем: по документации скрывать её можно только с подпиской
  Pro.

== Шаг 11. Тесты

* `WeekTimesheetServiceTest` — правила, под сотрудником с настоящими ролями:
** ячейка создаёт, меняет и удаляет списание; `0` — нет времени; то же время — не изменение;
** утверждённое, два списания, неактивная задача — отказ, и ничего не сохранено;
** неразборчивый текст — ошибка только этой ячейки;
** больше 24 часов в день — откат всей пачки;
** чужие списания и проекты не видны и не меняются;
** закрытая задача со списаниями недели остаётся строкой только для чтения.
* `WeekSheetViewUiTest` — серверная половина экрана без браузера. Событие браузера имитируется на
  сервере: `ElementListenerMap.fireEvent(new DomEvent(element, "week-sheet-change", data))`, где
  `data` — те же JSON, что присылает модуль:
** экран открывается по ссылке на неделю, у модели семь дней и строка задачи;
** правка включает Save, возврат к исходному тексту выключает; неизвестная строка игнорируется;
** Save сохраняет списание и показывает сохранённую неделю.

UI-тесты Jmix не запускают браузер, поэтому TypeScript-часть ими не проверяется: отрисовка, вставка,
протягивание, тема — ручная проверка в браузере.

== Сборка и развёртывание

* `./gradlew bootRun` — первый запуск после добавления пакета пересобирает dev-бандл.
* `./gradlew -Pvaadin.productionMode=true bootJar` — production-бандл с RevoGrid внутри jar.
* Docker (спека 04/02): `.dockerignore` пропускает `src/main/`, так что модуль `week-sheet.ts` попадает
  в сборку внутри образа; npm-пакет ставится на стадии сборки, кэш — в BuildKit.
* При первой сборке с npm-пакетом Vaadin создаёт в корне проекта `package.json`, `package-lock.json`,
  `tsconfig.json`, `types.d.ts`, `vite.config.ts`. Их принято хранить в git: `package-lock.json`
  фиксирует версии всех транзитивных пакетов. `node_modules` и `vite.generated.ts` уже в `.gitignore`.
* Сгенерированные Vaadin файлы (`package.json`, `node_modules`, `src/main/frontend/generated`) руками не
  правим: они перезаписываются при каждой сборке.

== Как заменить библиотеку

Всё, что знает о RevoGrid, — `week-sheet.ts` и `@NpmPackage` в `WeekSheet`. Чтобы взять, например,
Handsontable или Jspreadsheet CE:

. поменять `@NpmPackage` (пакет и версию);
. переписать `week-sheet.ts`, сохранив контракт элемента:
** свойства `model`, `errors`, `readOnly` с той же формой данных;
** событие `week-sheet-change` с `detail.changes = [{row, day, text}]`;
. подключить стили библиотеки, если она их не встраивает сама (у Handsontable — CSS из пакета).

Java-компонент, загрузчик, экран, сервис и тесты остаются как есть.

== Ограничения и что можно улучшить

* Правила 24 часов показываются сообщением, без подсветки ячеек: слушатель правил сообщает текст, но
  не ячейку.
* Возврат по истории браузера на другую неделю не спрашивает о несохранённых правках.
* Отмена и повтор (Ctrl+Z) — средствами RevoGrid внутри таблицы; после Save история не сохраняется.
* Описание списания в таблице не редактируется — только в форме списания.
